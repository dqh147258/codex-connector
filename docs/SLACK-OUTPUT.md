# Slack 输出、分页与观察边界

默认只发送安全命令结果和固定状态。普通 Slack 订阅不会把原生对话发给 Slack。双入口模式下，本机操作者可以单独开启**一个已核实会话的未来回复和普通问题**，只发送到授权时看到的那个 Slack 工作区、频道和根线程。其他会话、订阅和旧历史保持私有；仅 Slack 模式没有本机授权入口。

## 开启、检查与关闭正文分享

1. 使用双入口模式，确认 `servers` 对目标显示 `homeVerified:true`。用同一普通桌面账号、官方 Codex 实例和允许的项目。一个命名别名或同名会话不能作为 Home 或线程身份。
2. 在希望接收消息、且适合看到未来对话内容的 Slack 线程内请求 `session.subscribe {"threadId":"EXACT_CODEX_THREAD_ID","serverId":"default"}`。保存结果中的订阅 ID。这只是固定状态订阅，不会启动新任务，也不授权分享或控制。
3. 在本机操作者终端运行：

   ```sh
   node dist/src/cli.js native-share --operation grant --server default --subscription-id SUBSCRIPTION_ID
   ```

   核对实际原生会话、Slack workspace / channel / 根线程时间戳。命令会解释：**本机或其他客户端输入也可能影响未来分享到 Slack 的回复。** 同意才输入完整确认语句，直接回车取消。没有非交互自动确认开关。不要给 Agent 操作者令牌；Slack 和 scoped MCP 不能授予分享。
4. 将 `--operation` 改为 `inspect` 检查 `unshared`、`pending`、`checking`、`active`、`paused`、`gap` 或 `retired`，它们描述分享，不表示模型是否正在运行。改为 `revoke` 仅撤销正文分享；`session.unsubscribe` 会取消整个观察。撤销不会停止 Codex，也不会撤回已经发出的消息；正在请求 Slack 的消息仍可能到达。另一目的地必须重新授权，不会继承正文。

确认会先把授权可靠地写入本机，显示 `pending`，此时不排队、不转发。接着需要同一已核实 Home、原生会话和 Slack 目的地，在原生会话空闲时读取有序边界。知道该边界后才打开转发，显示 `active`。边界包含的所有轮次都不发送，包括授权前的轮次、之前已经在跑的轮次，以及确认后但已包含在边界里的轮次。请等看到 `active` 再启动想分享的工作。

如果会话忙（`NATIVE_SHARE_WAIT_UNTIL_IDLE`）或无法核实边界，保持 `pending`，同一授权在安全条件满足后可以打开，不需要重复点确认。重启不移用另一个目的地；还没有边界时只能取得新的合规边界，期间内容不会补发。已生效的边界被回滚或确认消失时会撤销，不自动猜测新边界。早期候选版缺少这道独立边界，已有授权需重新确认。

现有空线程若无法证明历史边界，请先撤销待开启的授权；然后用操作者本机 CLI 创建专用测试/分享会话（`command --name session.create --server default --params '{"project":"PROJECT_ALIAS"}'`），取得完成回执中的原生 threadId，在**发送任何内容前**订阅并授权它。专用会话仍需要支持有序历史的同一官方服务；若持续缺少证据，不能通过分页、文件、内存或截图绕过。

## 发送和不发送什么

- **发送：** 原生 App Server 有序记录中已完成、能确认是面向用户的助理阶段正文，包含正常回复、普通提问和面向用户的进度说明。已授权未来轮次的结构化 `requestUserInput` 可发送标题、问题和选项标签；只在同一原生连接仍看到当前请求时投递，提示回原生窗口回答。不会发送原生用户输入、回答内容、选项说明中的细节或内部 ID。不施加 Slack 提及，不把文本当指令。
- **不发送：** 流式增量、工具调用/参数/动作原始信息、日志、命令输出、隐藏推理、系统提示、审批或权限详情、秘密问题。不认识的结构、疑似敏感或操作性材料、含链接或超长的整条信息保留在原生窗。App 工具审批可能走相同问题接口；已核实的官方版本使用专用审批问题 ID，连接器拒绝该标记、关联工具项和疑似审批问题。已观察到的工具关联即使先于问题到达，也按对应 Home、会话和项目项保留并用于重连校验。达到证据上限时，结构化问题留在原生窗口，普通回复不受影响。回复上限为投影后 9,000 UTF-8 字节并做安全分片，结构化问题为 2,400 字节。格式和语义筛查是保守的启发式，不是全能的数据保护：可能拦住正常文字，也不能识别所有上下文敏感信息。仅面向适合看到该会话未来内容的读者开启。
- **不代答，不代审批：** Slack 回帖不会成为 Codex 回答，订阅不授予审批权。到期只更新 Connector 提醒；不发送原生响应、拒绝或中断。需要详细命令或安全决策时用原 Codex。
- **重连：** 用户回复按旧边界做有界只读补漏；不能证实连续性则显示 gap，不猜测。问题只接受当前连接的真实未答请求（若原生端能重送当前请求，也能识别）；不从历史猜测并重放。连接器不自动重做工作，不自动或人工重投已尝试且结果不明的正文。已观察到实际送达可登记现有 Slack 时间戳，不等于再次发送。
- 单独的屏幕捕获由本机权限对应的设置管理，默认关闭。它不是订阅的一部分；开启后手动截图可包含未遮盖的内容，授权正文分享不能授权捕获或扩大截图权限。

## 安全元数据、固定状态和命令结果

- `server.list` 列出已配置且当前身份获准的目标和缓存状态，不扫描。 `session.list` 默认 loaded，每来源最多 10 条。历史视图是元数据，不是内容；无法读取不等于 idle。 `session.recent` 使用有证据的生命周期时间排名。
- `result.page` 只读取同一身份、同一频道/线程的原安全快照；`result.next` 仅继续已获准的元数据查询。 `session.history`、`session.overview`、`session.messages`、`session.search` 不通过 Slack 搜索、调阅或补发历史正文。 `NATIVE_CONTENT_LOCAL_ONLY` 是边界，不是空结果。新分享内容不写入分页快照。
- `session.subscriptions` 列本认证身份在当前 Slack 线程内的订阅。未开启正文时，只有能归属到原 Slack 操作且仍在同一授权原线程的固定状态/提醒可能投递；不因本机附着、调整订阅或换线程而改变通道。连接错误或项目越界时不会转到其他位置。
- 命令结果和错误只发回已授权线程，不回退到频道顶层。显式 `session.reply` 只发送调用者自己输入的内容，不调用模型或获取原生正文。不要用本机 API、文件工具或截图绕过这条边界。查看自己授权的私有正文请用原生 Codex 窗口，或独立获权的本机 `session.history` / `events`。
