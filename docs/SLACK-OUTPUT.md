# Slack 输出、分页与观察边界

默认只发送安全命令结果和固定状态。**现有 Codex 会话在 Slack 里只能订阅状态，不能分享正文。** 需要在 Slack 收到 Codex 的回复或普通提问时，本机操作者可以在双入口模式下明确批准**新建一个专门分享的空白 Codex 会话**。它只会发往确认时看见的 Slack 工作区、频道和根线程。已有会话不会被复制、续接或分享。

## 新建分享会话、查询和关闭

1. 使用双入口模式，确认 `servers` 对目标显示 `homeVerified:true`。用同一普通桌面账号、官方 Codex 实例和允许的项目。
2. 在希望接收消息、且适合看到以后对话内容的 Slack 线程内请求 `session.subscribe {"threadId":"EXACT_CODEX_THREAD_ID","serverId":"default"}`。保存订阅 ID。这里只借用**已核实的 Slack 目的地和项目**，不会分享这个现有的 Codex 会话。
3. 在本机操作者终端运行：

   ```sh
   node dist/src/cli.js native-share --operation create --server default --subscription-id SOURCE_SUBSCRIPTION_ID
   ```

   核对原有会话、要创建新会话的项目、Slack 工作区／频道／根线程。命令会提示：**新空白会话中的回复和普通提问可能发给该线程，包括新会话设置期间开始的任务；本机或其他客户端的输入也可能影响分享的回复。** 只在同意这个范围时，手动输入终端给出的完整确认短语 `CREATE AND SHARE NEW CODEX SESSION TO …`。直接回车会取消。没有自动确认选项；不要给 Agent 操作者凭据。Slack 和 scoped MCP 不能创建分享。
4. 创建成功后，回执返回独立的 `newNativeThreadId` 与 `newSubscriptionId`。去 Codex 打开这个**新**会话，也可用获准的本机命令操作。使用 `--operation inspect` 加原订阅 ID 查看新建回执，或加新订阅 ID 查看 `pending`、`checking`、`active`、`paused`、`gap`、`retired` 等分享状态；这些状态不代表模型是否在运行。
5. 用 `--operation revoke` 加**新订阅 ID**可停正文分享，或在原 Slack 线程使用 `session.unsubscribe` 取消新订阅的整个观察。还没核实完成的新建请求，可用原订阅 ID 撤销。撤销不会停止 Codex，也不会撤回已送达的消息；若 Slack 已收到正在提交的 HTTP 请求，某条消息仍可能到达。另一个目的地不能继承这项授权。

确认先持久化，随后只调用官方 `thread/start` 新建独立空白会话。只有验证同一原生服务、新会话的独立身份和同一 Slack 目的地成功后，才开始投递。创建回执可信但监听尚未就绪时，不投递；只允许在新的独立会话就绪后发送合规的已完成回复，以及仍未得到回应、同一连接确实看到的普通结构化提问。若问题在创建确认前已发出，连接器不会先接收未知会话的数据；只对确认成功的新会话建立观察，原生服务可以重发仍待答的问题。请求回执先到、问题稍后到是正常的。无法核实待答但未收到合规问题时，会提示观察缺口；已关闭的结构化问题不会从历史重现。面向用户的已完成回复和普通文字提问仍按可验证原生记录补漏。列表索引可能落后，因此不能拿现有会话的历史、时间戳或当前“空闲”状态来授权正文。之前任何按“边界”分享既有会话的旧授权均已失效。

**刚新建的空会话可能还没有保存过一轮对话。** 若官方服务明确说这条已经验证的新会话没有持久记录，连接器仍可在创建它的同一连接上观察，不会撤销授权或发送一轮任务来初始化。断线换连接后，旧连接不再提供证明；先显示等待，只对这个确切会话做次数有限的重新观察。用户正常执行并保存首轮后，或重新建立连接时，可再次验证并补上仍在等待的原生问题。若达到重试上限仍无法确认，请查看原生会话或重新连接。已有会话不会因此开启正文分享。

如果新建显示 `uncertain`，这可能表示 Codex 已创建会话、但没有返回可验证的确认；连接器不会猜是哪条会话、不会授权未核实的会话，也不会自动重试。先用原生 Codex 查证，再决定是否从原订阅本机 `revoke` 清除不确定请求并另行确认创建。若创建已获证实但连接暂不可用，只会核对并重新观察同一个已证实的新会话，不创建替代会话。

### 可选：让指定真人在 Slack 选择答案

默认的新会话分享仍只能在原生 Codex 作答，不会把改版前的分享权限升级为答复权限。创建新专用会话时，本机操作者可额外指定 Slack 已获准真人的确切用户 ID：

```sh
node dist/src/cli.js native-share --operation create --server default --subscription-id SOURCE_SUBSCRIPTION_ID --answer-users USER_ID_A,USER_ID_B
```

预览和完整确认短语会列出这些人，以及确切目的地。Slack App 必须启用 Interactivity 并保持同一工作区、App 和 bot 身份；没有验证到互动身份时只发符合条件的文字提示，不发按钮。只有带「回答 Codex 问题」按钮的普通结构化选择题可以在 Slack 回答。被选定的真人点开原卡、选择答案、明确提交。没有按钮的普通文字提问、自由输入／Other、保密问题、所有工具/审批请求都应在原生 Codex 处理。普通 Slack 聊天、机器人和 Dot 不会成为答案。

每个入口针对真实送达的原 Slack 消息和一个仍待答的原生回调。答复先锁定一次提交再送出；「已提交」只表示 Connector 把答复写给原生连接，不表示 Codex 采用了它；其他客户端可能已回答。「请求已关闭」不说明是谁答的。无法确定是否送达或被采用时，请检查原生会话，Connector 不会自动重试。任一连接变化、撤销、问题改动或关闭使旧卡失效。新原生连接只在实际收到已重新核实的仍待答重放、原截止时间未变、旧答复未在途或不确定时，才可能发对应的新卡；不能从历史生成卡片。没有重放证据时会显示观察缺口，并提示返回 Codex。

本机 `native-share --operation inspect` 会给出脱敏问题计数与是否启用指定真人选择题答复。计数区分收到、投递、可答卡片、结构未知／敏感内容、工具证据、已关闭或覆盖缺口，不记录答案、问题正文或秘密。计数仅反映当前 Connector 进程。用户进入菜单看不到合规问题并不能证明原生没有提问。

## 发送和不发送什么

- **发送：** 新专用会话的 App Server 有序记录中已完成、能确认是面向用户的助理阶段正文，包含正常回复、普通提问和面向用户的进度说明。新专用会话的结构化 `requestUserInput` 可发送标题、问题和选项标签；只在同一原生连接仍看到当前请求时投递。默认提示回原生窗口；前面单独开启的指定真人答复只适用于按钮选择题。不会发送原生用户输入、回答内容、选项说明中的细节或内部 ID。不施加 Slack 提及，不把文本当指令。
- **不发送：** 流式增量、工具调用/参数/动作原始信息、日志、命令输出、隐藏推理、系统提示、审批或权限详情、秘密问题。不认识的结构、疑似敏感或操作性材料、含链接或超长的整条信息保留在原生窗。App 工具审批可能走相同问题接口；已核实的官方版本使用专用审批问题 ID，连接器拒绝该标记、关联工具项和疑似审批问题。已观察到的工具关联即使先于问题到达，也按对应 Home、会话和项目项保留并用于重连校验。达到证据上限时，结构化问题留在原生窗口，普通回复不受影响。回复上限为投影后 9,000 UTF-8 字节并做安全分片，结构化问题为 2,400 字节。格式和语义筛查是保守的启发式，不是全能的数据保护：可能拦住正常文字，也不能识别所有上下文敏感信息。仅面向适合看到该会话未来内容的读者开启。
- **不代答，不代审批：** 普通 Slack 回帖不会成为 Codex 回答，订阅不授予审批权。仅当获准真人对确切卡片明确提交合规选项时才会写入原请求；到期不会自动答复、拒绝或中断。需要详细命令或安全决策时用原 Codex。
- **重连：** 助理回复按同一专用会话的已核实游标做有界只读补漏；不能证实连续性则显示 gap，不猜测。问题只接受当前连接的真实未答请求（若原生端能重送当前请求，也能识别）；不从历史猜测并重放。连接器不自动重做工作，不自动或人工重投已尝试且结果不明的正文。已观察到实际送达可登记现有 Slack 时间戳，不等于再次发送。
- 单独的屏幕捕获由本机权限对应的设置管理，默认关闭。它不是订阅的一部分；开启后手动截图可包含未遮盖的内容，授权正文分享不能授权捕获或扩大截图权限。

## 安全元数据、固定状态和命令结果

- `server.list` 列出已配置且当前身份获准的目标和缓存状态，不扫描。 `session.list` 默认 loaded，每来源最多 10 条。历史视图是元数据，不是内容；无法读取不等于 idle。 `session.recent` 使用有证据的生命周期时间排名。
- `result.page` 只读取同一身份、同一频道/线程的原安全快照；`result.next` 仅继续已获准的元数据查询。 `session.history`、`session.overview`、`session.messages`、`session.search` 不通过 Slack 搜索、调阅或补发历史正文。 `NATIVE_CONTENT_LOCAL_ONLY` 是边界，不是空结果。新分享内容不写入分页快照。
- `session.subscriptions` 列本认证身份在当前 Slack 线程内的订阅。现有会话或其他未开启正文时，只有能归属到原 Slack 操作且仍在同一授权原线程的固定状态/提醒可能投递；不因本机附着、调整订阅或换线程而改变通道。连接错误或项目越界时不会转到其他位置。
- 命令结果和错误只发回已授权线程，不回退到频道顶层。显式 `session.reply` 只发送调用者自己输入的内容，不调用模型或获取原生正文。不要用本机 API、文件工具或截图绕过这条边界。查看自己授权的私有正文请用原生 Codex 窗口，或独立获权的本机 `session.history` / `events`。
