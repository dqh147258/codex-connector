# 简洁输出、分页与订阅

Slack 默认展示短摘要，不再把整个后端 JSON 自动拆成几十条消息。Desktop 的会话浏览页与本地 `/sessions` API 保持原有结构化数据和默认组合视图。

## 会话查询

`session.list` 增加 `view`：

- `loaded`：当前 shared daemon 已加载的 ID，逐个读取当前元数据。Slack 默认。
- `active`：只在当前 loaded 页中筛选新读取的 `active` 状态。不使用历史记录的 active 字段。
- `history`：已索引的交互会话历史，不代表当前正在运行。
- `all`：兼容组合视图；每个来源分别分页，可能同页有两组记录。

Slack 每来源最多 10 条，即使请求 `limit:100` 也显示实际执行上限。本地/桌面默认仍为 `all`、每来源 50 条，最多 100。每次只读取每个选中来源的一页，没有隐式扫描全部历史。`active` 页可能为零条但仍有下一页；未知元数据数量会单独给出，不能把它们视为 idle。数量是本页数量，不是全局总数。历史行明确标为 `history(current unknown)`。

例如严格命令信封中的 params 可为 `{"view":"active","limit":10}`。摘要包含精确结果句柄；用 `result.next {"resultId":"返回的ID"}` 获取同一筛选的下一页，无需复制长 cursor。也可以从详情取得完整 `nextCursor` 并在相同 view/project 的 `session.list` 中使用。每次命令使用新 request ID。游标绑定筛选上下文，不能跨筛选复用。

## 完整详情

`result.page {"resultId":"返回的ID","page":1}` 一次只返回一小页。页中的 text 按顺序拼接才是完整结果；它是带时间的快照，不是实时重新查询。读取详情不会重跑原来的 Codex 操作，也不会再生成一份快照。

- 必须是同一已验证发送者身份、同一 channel/thread。知道 ID 本身不构成授权。
- 最多保留 10 个、每个 250,000 字符的详情快照，最长可读取 15 分钟，也可能被新结果提前淘汰。修改权限/身份/根目录等配置会使旧句柄失效。
- 这是快照保留期限，不是 Slack 或本地投递历史的删除承诺。已经发送的消息及普通 outbox 历史仍按原有方式保存。
- 敏感内容检查在完整原始嵌套字符串上执行，再生成摘要；详情读取再次检查。超出大小或安全限制时明确告知不能提供详情，需要缩小查询或本地检查。检查是尽力防护，不是识别所有秘密的保证。
- 超长路径/名称/ID 会用 `…` 标出缩略，完整值在详情中，不能把缩略 ID 用于操作。
- 文件列表的结果详情覆盖本次有界读取的条目；`truncated:true` 不保证包含目录的全部内容。

长最终回答和显式回复默认只发预览。远程命令/订阅的详情仅属于原已验证发送者与原线程；自动绑定通知或本地 Skill 回复则交给绑定线程中的已配置可信 dot 身份。后者没有可用的可信 dot 时明确提示到原本地会话/来源读取。普通观察通知不传 token 流、原始工具日志或 reasoning。多片消息只在第一片 @dot；重试/重启不会把其余片重新变成 @ 通知。

审批/用户输入的完整提示不经过摘要器。未知、敏感、超大或范围不完整的审批仍要求本地处理。人类证明信封、身份校验、审批关联字段与一请求一决定规则没有放宽。

## 指定会话关键消息订阅

- `session.subscribe {"threadId":"精确的Codex线程ID"}`：把当前 Slack 命令线程作为固定接收位置。返回独立的 `subscriptionId`，不创建或移动控制绑定。
- `session.subscriptions {}`：列出当前发送者在当前 Slack 线程中的订阅，包括已停用项。
- `session.unsubscribe {"subscriptionId":"返回的订阅ID"}`：只有同一身份、同一 Slack 线程可取消。停止未来消息，并取消尚未发送的队列；正在 HTTP 发送中或已经被 Slack 接收的消息不能撤回。另一个人的显式订阅仍可能在同一公共线程继续推送。

订阅只面向当前 shared daemon 的 loaded ID；最多检查 20 页、1,000 个 ID，未确认的会话会明确拒绝而不是猜测最近会话。会话内容仍受独立的 sessionPolicy/项目范围约束，开启绝对路径文件读取不等于允许观察所有会话。`canAcceptDirectInput:false` 不妨碍观察已获准范围内的消息。

已完成的 assistant commentary、partial_answer、final_answer 消息，turn 完成/失败以及需要决定的状态会被转发。不传 token 流、工具 stdout、reasoning 或自动补读历史。每条携带原 thread/turn 标识；内容仍做敏感检查和长消息预览。支持的加入方式是 `thread/resume {threadId,excludeTurns:true}`，不发送 turn/start、queue、steer。它有连接/生命周期含义，loaded 检查与加入并非原子操作；服务器并发卸载时不能保证完全没有重新加载。不能据此承诺覆盖独立 CODEX_HOME 或 --no-daemon 实例。

取消仅关闭本地转发，不调用 Codex 的 thread/unsubscribe/interrupt，也不会结束工作。原有控制绑定默认仍保持原来的自动最终回答行为；如果在该绑定目的地显式订阅过，该目的地随后受订阅开关控制，取消不会再从旧自动路由漏出消息。已有控制绑定、发送权限和审批权限不因观察订阅而增加。

完整审批/用户输入提示只在原授权绑定目的地且路由启用时出现。其他观察位置仅收到“需回本地或原审批线程决定”的固定提示，不转发审批范围、响应模板或新增审批权限。仅观察、未绑定的回调不会由 Connector 自动回答。取消不是批准，也不会向 Codex 发决定。

订阅持久保存；重连先重新验证身份、范围和 loaded 状态，再加入。失败会停用并显示错误，绝不暗中启动任务或重新启用已经取消的订阅。最多保留 100 项（含取消记录），避免删除取消记录后旧自动路由复活。取消/恢复后的事件不是历史补播服务；已经观察过的事件会去重。

本版订阅控制由 Slack 严格命令提供，不在 Desktop 自动勾选，也不安装任何用户端 Skill。
