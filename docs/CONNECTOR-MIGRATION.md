# 迁移前预览与回滚

在**连接器电脑上**运行 `node dist/src/cli.js migration-preview --home /你的/连接器目录`；默认目录可省略。预览只读旧版根目录的 Connector `state.json` 和必要的 `config.json` 字段。不读 Codex 会话、Home、socket、令牌，不启动服务，不获取锁，也不创建目录或备份。最多读取 64 MiB 状态；损坏、特殊或过大的文件会拒绝。服务运行时可预览，但状态可能继续变化；请停服务后再做实际迁移。

- `absent`：没有旧根账本。`already-pinned`：已有目标指纹，此预览不认证实际后端、也不比较指纹。
- `legacy-single-default`：配置只有规范 ID 为 `default` 的目标。先核实它确实是原来的物理目标。首次启动前先自行保留原配置和整个连接器状态目录；启动时连接器会在该目录第一次生成 `state.before-server-profiles.json`（已存在则不覆盖）。旧待执行/执行中的工作、待发送/发送中的 Slack 投递转为不确定，待处理/正在响应的批准转为失效。不会替你重发、重跑或同意。预览只显示各类条数，不显示消息、会话名或凭据。
- `legacy-blocked`：无法把旧数据唯一归给可兼容的默认目标，整份旧账本不应参与执行。单独配置多个目标，不等于旧记录自动属于某个目标；**不要删锁、改指纹或利用别名碰运气**。先恢复旧配置，核对目标和已执行的动作，再决定迁移方式。

**回滚**：先正常停止全部使用该状态目录的 Connector 进程，确认已退出。将迁移后的完整目录另行私有备份，再用**迁移前留存的配置和对应版本的完整目录**恢复，配套切回之前的程序版本。如只恢复兼容的单默认账本，先核实首次备份属于这次迁移且没有更新的有效数据，再由操作者将 `state.before-server-profiles.json` 的副本还原到 `state.json`。这不是撤销 Codex 或 Slack 已经执行的动作；恢复旧队列可能重放，先人工核对不确定项，不要直接重启旧队列。
